# DNS management v2 wire fixtures

These synthetic, non-secret fixtures are GENERATED BY THE SERVER SERIALIZERS:
`WorkerReadResponse` and the v2 status envelope. They bind the server DTOs to
the worker's strict parser and reporter for the additive schema-v2 config and
cache-clear command. They are test inputs, never fetched lists or real policy.

`read.json` carries `schema_version: 2`, a `config_v2` object with the frozen
v1 fields plus the supported runtime cache/response settings, and one pending
cache-clear token. `report.json` carries its truthful attempt/ack. The digest
`4652ce3244e14658db02de0c05520507d0d92619a434a6a455a8309f5dbb6d37` is the
SHA-256 of the exact canonical `config_v2` bytes, recomputed independently by
both validators. The v1 fixtures and their golden SHA remain unchanged.

Validation uses the fixed `server_time`, so the original `applied_at` and
command times stay reproducible. An old v1-only worker rejects `config_v2`
with its strict parser, records the error honestly and never commits or
poisons last-known-good.
